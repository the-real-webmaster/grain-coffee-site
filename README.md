## 📖 О проекте

**GRAIN** — концепт-сайт для современной спешелти-кофейни: собственная обжарка, авторские напитки и тёплая городская атмосфера. Проект сделан как демонстрация чистой вёрстки без фреймворков — с продуманной дизайн-системой на CSS-переменных, двумя полноценными темами, тематической фотографией вместо случайных заглушек, вниманием к SEO/доступности и базовой защитой на уровне статического сайта.

> Все тексты, фотографии и контактные данные — демонстрационные. Фото подключены с Unsplash по прямым ссылкам (не требуют API-ключа) — перед боевым запуском замените их на собственные снимки кофейни (см. раздел [«Как кастомизировать»](#-как-кастомизировать)).

## 🛠️ Технологии

- **HTML5** — семантическая вёрстка (`header`, `nav`, `main`, `section`, `article`, `footer`)
- **CSS3** — кастомные свойства (переменные) для тем, Grid/Flexbox, `clamp()`, `color-mix()`, без препроцессоров и фреймворков
- **Vanilla JavaScript** — своя логика без зависимостей, разбита на независимые функции-инициализаторы, весь JS вынесен во внешний файл (никаких инлайн-скриптов)
- **[AOS](https://michalsnik.github.io/aos/) (Animate On Scroll)** — появление блоков при скролле; подключена через cdnjs с проверкой целостности (SRI `integrity`)
- **[Swiper](https://swiperjs.com/)** — свайпаемая карусель отзывов на главной (`index.html` → `.testimonials-track.swiper`, инициализация в `initTestimonialsCarousel()`); тоже с cdnjs + SRI. До инициализации JS `.swiper-wrapper` — обычная CSS grid-сетка, так что если библиотека не загрузится, отзывы просто остаются в виде сетки, ничего не ломается
- **Google Fonts** — Fraunces (заголовки) + Manrope (текст)
- **Фотография** — тематические снимки с Unsplash (прямые ссылки на CDN, без стороннего JS-виджета), собственный SVG-логотип и мелкие line-art иконки для навигации/буллетов

## 🚀 Как запустить

Проект не требует сборки и локальных зависимостей (AOS подключается через CDN, интернет нужен только для загрузки шрифтов/AOS/фото).

**Вариант 1 — просто открыть файл**
Откройте `index.html` двойным кликом в любом современном браузере.

**Вариант 2 — через live-server (рекомендуется)**
Чтобы корректно работали относительные пути и не было CORS-ограничений:

```bash
npx live-server
# или, если установлен глобально
live-server
```

Либо через расширение **Live Server** в VS Code.

## ✨ Реализованные фичи

### 🎨 Дизайн и темы
- Светлая (тёплый крем + терракотовый акцент) и тёмная (графит + карамельно-медный акцент со свечением) темы
- Переключатель темы в хедере с иконкой солнце/луна и плавной анимацией (~350 мс)
- Тема сохраняется в `localStorage` и уважает `prefers-color-scheme` при первом визите
- Вся палитра — на CSS custom properties, замена цвета в одном месте меняет весь сайт
- Все текстовые/фоновые пары цветов (кнопки, теги, бейджи, ссылки, hover/active/focus-состояния) проверены и подобраны под контраст **не ниже 4.5:1 (WCAG AA)** в обеих темах — включая известную ловушку с CSS-специфичностью (`.main-nav a` тяжелее `.btn-primary`), из-за которой текст кнопки в шапке мог слиться с фоном; исправлено отдельным точечным правилом в `styles.css`

### 🖼️ Фотография
- Все изображения сайта — тематические фотографии кофеен, напитков, зёрен и портретов с Unsplash (`images.unsplash.com`, прямые CDN-ссылки на конкретные снимки, а не случайная генерация) — под каждый блок подобрано своё фото, без повторов рядом друг с другом
- Явных обёрток-плейсхолдеров нет — `<img>` со своими `width`/`height`/`aspect-ratio` контейнера, `object-fit: cover` и лёгким zoom по hover (`.cover-img`)
- Круглые фотопортреты команды/отзывов — класс `.avatar-photo`
- Все места для замены отмечены комментариями `<!-- ЗАМЕНИТЬ: ... -->` прямо в HTML

### 🧭 Навигация и интерактив
- Полноэкранное мобильное меню на бургере: ссылки появляются по очереди с лёгким сдвигом (не резким рывком), текущая страница подсвечена «таблеткой», CTA-кнопка на всю ширину внизу списка, а под ней — часы работы и соцсети (`.main-nav-foot`)
- Мобильное меню полностью доступно с клавиатуры: `Esc` закрывает, `Tab`/`Shift+Tab` не выходит за пределы панели (focus trap), фокус возвращается на кнопку-бургер после закрытия, подпись кнопки синхронизирована с состоянием («Открыть меню» / «Закрыть меню»)
- Фильтры меню/галереи на узких экранах превращаются в горизонтальную ленту с snap-прокруткой вместо переноса на несколько строк
- Якорные ссылки (например, из футера на `menu.html#espresso`) корректно останавливаются под «прилипшим» хедером — `scroll-padding-top` учитывает его высоту, которая на мобильных меньше (`--header-h`)
- Плавный скролл (`scroll-behavior: smooth`)
- Появление секций при скролле через библиотеку **AOS** (`data-aos="fade-up"` в разметке, `AOS.init()` в `js/script.js`) — если библиотека не загрузилась (офлайн, заблокирован CDN), контент остаётся видимым как есть, ничего не ломается
- Декоративная вращающаяся подсветка за фото в hero, лёгкий parallax-эффект декоративных элементов по движению мыши
- Лёгкий 3D-tilt карточек меню/блога/отзывов при наведении мышью (только на устройствах с точным указателем, отключается при `prefers-reduced-motion`)
- Тонкая «зерновая» текстура (SVG `feTurbulence`) на фоне hero-секции
- Индикатор загрузки страницы с аварийным таймером (если событие `load` почему-то задерживается — заглушка всё равно скрывается не позже, чем через 2.5 c)
- Фильтрация карточек в меню и галерее без перезагрузки страницы
- Lightbox для галереи с клавиатурной навигацией (←/→/Esc)
- Валидация и имитация отправки формы обратной связи

### 🔍 SEO и доступность
- Уникальные `title`, `description`, `keywords` на каждой странице
- Open Graph и Twitter Card мета-теги (изображение — собственный `assets/og-image.svg`, без обращения к сторонним сервисам)
- JSON-LD микроразметка `CafeOrCoffeeShop` / `Article`
- Иерархичные заголовки `h1–h3` без пропусков уровней
- `alt`-описания у всех фотографий, `loading="lazy"` вне зоны видимости (кроме hero-изображения — оно загружается сразу)
- `sitemap.xml` и `robots.txt`
- Skip-link, `aria-label`/`aria-current`, видимый `:focus-visible` во всех темах для навигации и интерактивных элементов

## 🔒 Безопасность

Сайт статический (HTML/CSS/JS без бэкенда), поэтому часть защитных мер реализована на уровне фронтенда, а часть — вынесена в конфиги хостинга, которые нужно настроить при деплое.

### Что уже сделано во фронтенде

- **Весь собственный JS — во внешнем файле.** Ни на одной странице нет инлайн-`<script>` с логикой (JSON-LD-блоки `type="application/ld+json"` не в счёт — это данные для поисковиков, а не исполняемый код; современные браузеры не применяют к ним `script-src`). Единственный подключённый внешний скрипт — библиотека AOS с cdnjs, загружается с атрибутом `integrity` (Subresource Integrity): если файл на CDN подменят, браузер откажется его выполнять.
- **CSP через `<meta http-equiv="Content-Security-Policy">`** на каждой странице: `script-src 'self' https://cdnjs.cloudflare.com`, `style-src 'self' https://fonts.googleapis.com https://cdnjs.cloudflare.com` (без `'unsafe-inline'` — в разметке нет ни одного `style="..."`, все точечные отступы вынесены в CSS-утилиты типа `.u-mt-2`), `img-src 'self' https://images.unsplash.com data:`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'` и т.д.
- **Форма обратной связи (`contacts.html`):**
  - клиентская валидация обязательных полей и формата email перед «отправкой»;
  - **honeypot-поле** `company` — визуально и с клавиатуры недоступно человеку (`.form-honeypot`, `tabindex="-1"`, вне видимой области, не `display:none`, чтобы примитивные боты не игнорировали его), но видно ботам, которые заполняют все поля формы подряд; если оно заполнено — отправка молча отклоняется в `initContactForm()` (`js/script.js`);
  - персональное приветствие в сообщении об успехе («Спасибо, Имя!») выводится через `textContent`, а не `innerHTML` — значение из поля «Имя» физически не может внедрить HTML/скрипт; в `js/script.js` также есть переиспользуемая функция `escapeHTML()` на случай, если в будущем понадобится подставлять пользовательский текст в HTML-шаблон.
- **`rel="noopener noreferrer"`** на всех внешних ссылках с `target="_blank"` (иконки соцсетей в футере) — защита от [tabnabbing](https://owasp.org/www-community/attacks/Reverse_Tabnabbing).
- **`<meta name="referrer" content="strict-origin-when-cross-origin">`** — контролируемая утечка Referer при переходах на другие сайты.

### Что нужно донастроить на сервере при деплое

Часть заголовков браузеры применяют **только** если они пришли по HTTP, а не из `<meta>` (спецификация прямо запрещает `frame-ancestors` в meta-CSP, `X-Frame-Options` и `X-Content-Type-Options` через meta браузеры тоже игнорируют). Поэтому в комплекте три готовых конфига — подключите тот, что соответствует вашему хостингу, остальные два можно удалить:

| Файл | Хостинг |
|---|---|
| `.htaccess` | Apache / LiteSpeed |
| `netlify.toml` | Netlify |
| `vercel.json` | Vercel |

Во всех трёх выставлены одинаковые заголовки:
- `X-Frame-Options: SAMEORIGIN` — запрет встраивания сайта во фрейм на чужом домене (clickjacking);
- `X-Content-Type-Options: nosniff` — запрет MIME-sniffing;
- `Referrer-Policy: strict-origin-when-cross-origin`;
- `Permissions-Policy` — отключены неиспользуемые API браузера (геолокация, камера, микрофон и т.д.);
- полноценный `Content-Security-Policy` с директивой `frame-ancestors 'self'` (недоступна через meta-тег).

Дополнительно перед боевым запуском:
- **HTTPS обязателен.** Большинство современных хостингов (Netlify, Vercel, Cloudflare Pages) включают его автоматически; для своего сервера — Let's Encrypt/сертификат от хостинг-провайдера.
- **HSTS** (`Strict-Transport-Security`) в конфигах закомментирован — включайте его только когда HTTPS гарантированно работает всегда и для всех поддоменов, иначе можно на длительный срок отрезать себе доступ по http.
- **Форма обратной связи** сейчас ничего никуда не отправляет (см. `TODO` в `contacts.html` и `js/script.js`). При подключении реального бэкенда/сервиса форм обязательно продублируйте валидацию на сервере — honeypot и клиентская проверка не защищают от целенаправленного бота, который просто шлёт POST-запрос напрямую, минуя форму; там же стоит добавить рейт-лимит и капчу.
- Если подключаете внешние сервисы (карты, аналитику, свои фото с другого CDN) — не забудьте добавить их домены в `Content-Security-Policy` (и в `<meta>`, и во всех трёх конфигах хостинга), иначе браузер их заблокирует.

## 🎨 Как кастомизировать

### Логотип
Замените `assets/logo.svg` и `assets/favicon.svg` на свои. Логотип использует `stroke="currentColor"` — цвет наследуется автоматически, отдельная версия под тёмную/светлую тему не нужна.

### Цвета и темы
Все цвета собраны в `css/styles.css`, в блоках `:root[data-theme='light']` и `:root[data-theme='dark']`. Достаточно поменять значения `--color-accent`, `--color-bg` и соседние переменные. При замене палитры перепроверьте контраст текста на новых цветах (минимум 4.5:1 для обычного текста) — например через DevTools → Contrast или [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/). Особое внимание — кнопкам/ссылкам внутри навигации: у `.main-nav a` в CSS выше специфичность, чем у одиночного класса `.btn-primary`, поэтому цвет текста кнопок в шапке задан отдельным правилом `.main-nav a.btn-primary` — если добавляете новую кнопку в `<nav>`, скопируйte этот паттерн, а не полагайтесь на обычный `.btn-primary`.

### Шрифты
Подключены через `@import` в начале `styles.css`. Чтобы заменить — обновите URL Google Fonts и переменные `--font-heading` / `--font-body`, а также домен `fonts.googleapis.com`/`fonts.gstatic.com` в `Content-Security-Policy` (в `<meta>` на каждой странице и в конфигах хостинга), если смените провайдера шрифтов.

### Фотографии
- Все `<img>` со ссылками на `images.unsplash.com` отмечены соседними комментариями `<!-- ЗАМЕНИТЬ: ... -->`. Чтобы подставить свои фото — просто замените `src` на путь к своему файлу (например `assets/photos/hero.jpg`) и обновите `alt`, `width`/`height` можно оставить (задают только соотношение сторон для резервирования места) либо привести в соответствие реальному размеру файла.
- Если подключаете фото с внешнего CDN (не Unsplash) — добавьте его домен в `img-src` вашего `Content-Security-Policy` (в `<meta>` каждой страницы и во всех трёх конфигах хостинга).
- Классы `.cover-img` (прямоугольные карточки, `object-fit: cover` + zoom по hover) и `.avatar-photo` (круглые портреты) можно переиспользовать для новых блоков.

### Анимации скролла (AOS)
Элементы, которые должны появляться при скролле, помечены `data-aos="fade-up"` (и `data-aos-duration="700"`). Полный список эффектов и настроек — в [документации AOS](https://michalsnik.github.io/aos/). Чтобы отключить анимации совсем — удалите строки с `<link>`/`<script>` AOS из `<head>`/перед `</body>` и вызов `initScrollAnimations()` в `js/script.js`; вёрстка и так корректно отображается без JS (`data-aos` — это просто HTML-атрибут).

### Карта
В `contacts.html` вместо интерактивной карты — стилизованная заглушка `.map-placeholder`. Замените её на `iframe` Яндекс.Карт или Google Maps с реальным адресом (не забудьте добавить домен карты в `frame-src`/`img-src` вашего `Content-Security-Policy`).

### Форма обратной связи
Форма в `contacts.html` сейчас имитирует отправку (см. `initContactForm()` в `js/script.js`). Подключите свой backend или сервис форм (Formspree, свой API и т.п.) в обработчике `submit` — и обязательно продублируйте валидацию/антиспам на сервере (см. раздел [«Безопасность»](#-безопасность)).
